# iOS 登录与后台余额刷新

## 1.0.6：修复跨日首次登录返回标题

保留原 DMM 插件的认证时序：创建 `AuthLoginRequest` 时复位，认证请求使用 DMM；有效 `AuthLoginResponse` 解析完成后允许 iOS 平台模拟。充值拦截独立生效。

RE 额外提供的首次余额刷新必须等待 `Home:Login` 成功。`User:Get` 创建余额模型不代表每日登录已经完成。成功事件取自游戏的 `ApiSuccessLog`，仅解析到 `HomeLoginResponse` 不触发刷新；重新认证会清除等待状态。

热启用和停用仍主动刷新对应平台余额。所有插件主动发出的 `User:GetBalance` 都使用独立的 `ApiCallOption`，关闭这条后台请求的默认错误处理和加载事件。失败保留当前显示并报告错误码，不触发游戏返回标题；正常游戏请求的错误处理不变。

### 实际故障证据（2026-11-24）

- 14:52:25.730：`User:Get` 成功。
- 14:52:25.821：插件立即发出 `User:GetBalance`。
- 14:52:26.076：服务器返回错误码 2006、`Action=title`。客户端元数据中 2006 对应 `DateChanged`，不是 `OutdatedApp`（2004）。
- 14:52:26.456：DMM 购买服务初始化成功。故障不能归因于 DMM 初始化失败。
- 关闭插件后，15:19:03.878 发出 `Home:Login`，15:19:06.741 成功，之后继续每日登录奖励和进入主页。

故障源于额外余额查询早于每日登录，并使用游戏默认错误处理；不能据故障恰好发生于更新后就认定 3.6.1 改变了登录流程。凌晨查询成功也未覆盖跨日后的首次登录。

### 验证范围

框架仓库 `Tests/IosLoginTests.cs` 的回归在旧插件上复现了提前查询，在 1.0.6 上通过。覆盖每日登录前禁止查询、仅成功响应触发一次刷新、重登复位、2006/title 不引发标题跳转或加载事件、热启停、失败保留、迟到响应及余额并发更新。

这些是离线模拟与本机历史日志分析；修复版的游戏内首次登录和跨日验证仍需实测。没有通过修改服务器响应、伪造余额或关闭游戏正常错误处理来让测试通过。
